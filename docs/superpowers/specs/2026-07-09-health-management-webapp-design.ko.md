# 건강관리 웹앱 설계

## 요약

식단과 매일의 몸상태를 관리할 수 있는 웹앱을 만든다. 첫 버전은 Next.js 웹앱, Supabase 인증/데이터베이스, 규칙 기반 로직과 AI를 섞은 식단 추천 엔진, Vercel 배포를 사용한다.

앱은 이메일/비밀번호 회원가입, 온보딩 프로필 작성, 일주일 식단 생성, 매일 몸상태 체크인, 현재 컨디션에 따른 식단 조정, 운동/생활습관/일반의약품 정보 안내를 제공한다. 약 정보는 진단이나 처방이 아니라 일반 정보로 제한하고 안전 안내를 함께 보여준다.

## 목표

- 사용자가 이메일과 비밀번호로 가입하고 로그인할 수 있다.
- 나이, 생년월일, 키, 몸무게, 체중 목표, 건강 고민, 현재 몸상태, 좋아하는 음식, 피하고 싶은 음식을 입력받는다.
- 개인화된 일주일 식단표를 생성한다.
- 사용자가 매일 간단 체크인과 선택적 상세 메모로 몸상태를 기록할 수 있다.
- 최근 체크인에 따라 식단 추천을 갱신하거나 조정한다.
- 운동, 생활습관, 영양, 일반의약품 정보를 포함한 상태 개선 정보를 제공한다.
- 앱을 공개 웹주소로 배포해서 다른 사람도 접속할 수 있게 한다.

## 첫 버전에서 하지 않는 것

- iOS/Android 네이티브 앱 배포
- 의료 진단, 처방, 응급 의료 조언
- 약국 구매 연결
- 웨어러블 기기 연동
- 음식 사진 기반 자동 칼로리 추적
- 전체 사용자 관리용 관리자 대시보드

## 제품 흐름

### 1. 인증

사용자는 이메일과 비밀번호로 가입하고 로그인한다. Supabase Auth가 계정 생성, 로그인 세션, 비밀번호 재설정, 사용자 식별을 담당한다.

### 2. 온보딩

첫 로그인 후 사용자는 온보딩 폼을 작성한다.

- 이름 또는 닉네임
- 생년월일
- 가능하면 생년월일에서 계산한 나이
- 키
- 몸무게
- 체중 목표: 감량, 유지, 증량
- 건강 고민: 피로, 소화, 수면, 근육 증가, 혈당 관리 등
- 현재 몸상태
- 좋아하는 음식
- 피하고 싶은 음식, 알레르기, 식이 제한

알레르기와 주요 식이 제한은 식단 추천에서 반드시 지켜야 하는 강한 제약으로 다룬다.

### 3. 대시보드

로그인 후 메인 화면이다. 다음 정보를 보여준다.

- 오늘 체크인 상태
- 현재 일주일 식단표
- 최신 체크인에 따른 오늘의 조정 추천
- 몸상태 입력, 식단 재생성, 건강 정보 보기 바로가기

### 4. 일주일 식단표

식단표 화면은 7일치 식사를 보여준다. 각 날짜는 아침, 점심, 저녁, 선택적 간식을 포함한다. 각 식사에는 사용자 프로필과 목표에 맞는 이유를 짧게 설명한다.

사용자는 프로필이 바뀌거나 매일 체크인에서 의미 있는 변화가 생겼을 때 식단표를 다시 생성할 수 있다.

### 5. 매일 몸상태 체크인

체크인은 두 단계로 제공한다.

- 간단 체크인: 컨디션 점수, 수면 품질, 스트레스, 운동 여부, 식욕, 소화, 증상 심각도
- 상세 입력: 메모, 구체 증상, 물 섭취량, 식사 피드백, 통증/불편 부위, 자유 메모

매일 쓰는 기능이므로 기본 체크인은 빠르게 완료할 수 있어야 한다.

### 6. 건강 정보

건강 정보 화면은 사용자 프로필과 최신 체크인에 따라 상태 개선 정보를 제공한다.

- 운동 추천
- 스트레칭과 회복 방법
- 수면과 수분 섭취 팁
- 영양 정보
- 필요한 경우 일반의약품 또는 성분 정보

약 정보는 진단이나 처방처럼 표현하지 않는다. 심한 증상, 임신, 만성질환, 어린이, 알레르기, 약물 상호작용, 증상 지속 상황에서는 의사나 약사 상담을 권고한다.

## 추천 설계

앱은 규칙 기반 로직과 AI를 섞은 추천 방식을 사용한다.

### 규칙 기반 계층

규칙 기반 계층은 다음을 계산하거나 제한한다.

- 키와 몸무게 기반 BMI 범주
- 체중 목표에 따른 방향성
- 정확한 의료 조언처럼 보이지 않는 기본 칼로리 방향
- 알레르기, 피하고 싶은 음식, 식이 제한 제외
- 단백질, 채소, 탄수화물, 수분 중심의 식사 균형
- 전문 진료가 필요한 증상에 대한 안전 경계

이 계층은 AI에 전달할 구조화된 추천 요청을 만든다.

### AI 계층

AI 계층은 다음을 생성한다.

- 식사 이름과 설명
- 7일치 식단 다양성
- 사용자에게 맞는 이유
- 사용자가 싫어하는 메뉴에 대한 대체 식사
- 운동과 생활습관 정보를 친근한 문장으로 요약

AI 프롬프트에는 안전 지침, 제외 음식, 진단/처방 금지 조건을 반드시 포함한다.

### 식단 갱신 로직

앱은 다음 상황에서 식단을 갱신하거나 조정한다.

- 사용자가 온보딩을 처음 완료했을 때
- 프로필, 목표, 좋아하는 음식, 피하고 싶은 음식, 건강 고민을 수정했을 때
- 최신 일일 체크인이 최근 기준과 의미 있게 달라졌을 때
- 사용자가 직접 재생성을 요청했을 때

작은 일일 변화는 전체 식단표를 교체하지 않고 “오늘의 조정 추천”으로 보여줄 수 있다.

## 아키텍처

### 프론트엔드

Next.js App Router와 TypeScript를 사용한다. 화면은 다음을 포함한다.

- 인증 화면
- 온보딩
- 대시보드
- 식단표
- 매일 체크인
- 건강 정보
- 프로필 설정

UI는 모바일 브라우저를 우선으로 반응형 설계하고, 데스크톱에서도 잘 동작해야 한다.

### 백엔드

Next.js server actions 또는 route handlers를 사용한다.

- 온보딩 데이터 저장
- 매일 체크인 저장
- 식단 생성
- 건강 정보 생성
- 대시보드 데이터 조회

Supabase가 인증과 데이터 저장을 담당한다. Row Level Security로 각 사용자가 자신의 데이터만 접근할 수 있게 한다.

### AI 연동

AI 연동은 서버 코드 뒤에 둔다. API 키는 브라우저에 노출하지 않는다.

생성 흐름:

1. 사용자 프로필과 최신 체크인을 불러온다.
2. 규칙 기반 건강/식단 제약을 계산한다.
3. 구조화된 AI 요청을 만든다.
4. AI 응답 형식을 검증한다.
5. 생성된 식단 또는 건강 정보를 저장한다.
6. 결과를 사용자에게 보여준다.

## 안전과 준수

- 온보딩과 약 관련 정보 근처에 건강 정보 안내 문구를 보여준다.
- 식사, 운동, 약이 특정 상태를 치료한다고 주장하지 않는다.
- 심각하거나 긴급한 증상은 일반 추천 대신 전문 진료 안내를 보여준다.
- 알레르기와 피하고 싶은 음식은 높은 우선순위로 제외한다.
- 약 정보는 일반 성분/분류 정보에 집중하고 의사 또는 약사 상담을 권고한다.

## 오류 처리

- AI 생성이 실패하면 재시도 화면을 보여주고 기존 식단이 있으면 유지한다.
- 프로필 데이터가 부족하면 온보딩 또는 설정으로 안내한다.
- Supabase 세션이 만료되면 로그인으로 이동한다.
- 생성된 결과가 검증에 실패하면 저장하지 않고 재생성을 안내한다.

## 테스트

초기 테스트는 다음을 다룬다.

- BMI와 체중 목표 방향 계산
- 제외 음식 처리
- 매일 체크인 저장과 조회
- 식단 생성 응답 검증
- 가능하면 Row Level Security 전제에 대한 통합 확인
- 주요 사용자 흐름: 가입, 온보딩, 체크인, 식단표 조회, 재생성

## 배포

웹앱은 Vercel에 배포한다. Supabase는 인증과 데이터베이스를 호스팅한다. 필요한 환경 변수는 다음과 같다.

- Supabase 프로젝트 URL
- Supabase anon key
- 필요한 경우 서버 전용 Supabase service role key
- AI 제공자 API key

첫 공개 배포에는 베타 표시와 건강 정보 안내 문구를 포함한다.

## 첫 버전 성공 기준

- 새 사용자가 가입하고 온보딩을 완료한 뒤 일주일 식단표를 볼 수 있다.
- 기존 사용자가 로그인해서 기존 식단표를 볼 수 있다.
- 사용자가 매일 체크인을 제출할 수 있다.
- 체크인이 식단 조정 또는 재생성을 유도할 수 있다.
- 사용자가 운동, 생활습관, 영양, 안전한 일반의약품 정보를 볼 수 있다.
- 앱이 공개 웹주소로 배포된다.
